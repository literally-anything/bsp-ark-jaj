# bsp-ark-jaj

[Avocado OS](https://avocadolinux.org) board support for the
[ARK Electronics Just A Jetson](https://docs.arkelectron.com/products/embedded-computers/ark-just-a-jetson)
(JAJ) carrier with an NVIDIA Jetson Orin NX module.

It works like Avocado's own carrier boards (for example the Advantech ICAM-540):
a **carrier extension on the generic `jetson-orin-nx` target**. It replaces
`avocado-bsp-jetson-orin-nx`. Don't use both.

| Extension | Module | SOM SKU |
|---|---|---|
| `avocado-bsp-ark-jaj-nx16` | Jetson Orin NX 16GB | P3767-0000 |
| `avocado-bsp-ark-jaj-nx8` | Jetson Orin NX 8GB | P3767-0001 |

There is one extension per module because Avocado fixes the flash settings per
SOM SKU: DTB, BPMP DTB, SDRAM configuration and the EEPROM SKU check. Flashing
the wrong variant fails the tegraflash SKU check before anything is written.

Built and tested against Avocado 2024/edge (jetson-orin-nx snapshot 17, kernel
6.6.127, L4T 36.5) with avocado-cli 1.0.0-rc.5.

## Using it

Declare the variant(s) in your project with a **git source pinned to a release
tag**:

```yaml
supported_targets:
  - jetson-orin-nx

extensions:
  avocado-bsp-ark-jaj-nx16:
    source: { type: git, url: https://github.com/literally-anything/bsp-ark-jaj, ref: '0.1.0' }
  avocado-bsp-ark-jaj-nx8:
    source: { type: git, url: https://github.com/literally-anything/bsp-ark-jaj, ref: '0.1.0' }
```

Always use a tag for `ref`. avocado-cli 1.0.0-rc.5 clones with
`git clone --branch <ref>`. For a commit hash that fails, it falls back to
cloning the default branch, and the checkout of the hash fails silently, so you
build the branch tip instead. The lock file doesn't record the commit either.

The extension names follow the `avocado-bsp-<board>` convention, so a runtime
that lists `avocado-bsp-{{ avocado.target.board }}` picks the right one from the
target board:

```sh
avocado install -r dev --target jetson-orin-nx --target-board ark-jaj-nx16
avocado build   -r dev --target jetson-orin-nx --target-board ark-jaj-nx16
avocado provision dev --target jetson-orin-nx --target-board ark-jaj-nx16
```

`AVOCADO_TARGET` and `AVOCADO_TARGET_BOARD` work too. The runtime needs
`jetson-orin-nx` in its `target:`/`targets:`, and your SDK needs
`avocado-sdk-toolchain` (the default project has it) for the nvpmodel step
below.

### Only one `carrier-bsp/` is used

The flash takes the whole `carrier-bsp/` folder from the first include path
that has one. If your project stages its own flash overrides, for example extra
UEFI settings, it must merge this board's slot rather than add a second one.
Copy `stone/<extension>/carrier-bsp/`, append to `carrier.env`, and put the
result on a runtime-level `stone_include_paths` entry, which is searched before
extensions. Each variant's slot is in a folder named after its extension, so a
merge script can find the slot of the extension it actually uses.

## What's in it

### Flash time: `stone/<extension>/carrier-bsp/`

Generated by `scripts/build-carrier-bsp.sh` from the pinned inputs in
`upstream.env`. Nothing here is hand-edited:

| File | What it is |
|---|---|
| `tegra234-p3768-0000+p3767-<sku>-nv-super-ark-jaj.dtb` | Avocado's own stock DTB for the SKU, plus ARK's JAJ fragment (`src/ark/ark-JAJ-overrides.dtsi`), ARK's model string, and ARK's dual IMX219 camera overlay applied on top |
| `tegra234-mb1-bct-pinmux-…-ark-jaj.dtsi`, `…-gpio-…-ark-jaj.dtsi` | ARK's MB1 pinmux/GPIO: IMU on spi3 and UART-A RTS/CTS set at power-on, I2S0 pins safe from power-on, and more |
| `tegra234-mb2-bct-misc-p3767-0000-ark-jaj.dts` | Stock MB2 misc with `cvb_eeprom_read_size = 0` (ARK's only change to it) |
| `ark-jaj-boot-order.dtbo` | ARK's UEFI overlay: NVMe before USB, and new devices (PXE/HTTP boot options) at the bottom |
| `carrier.env` | Retargets the flash at the files above and pins the SKU check (plus BPMP DTB, chip SKU and SDRAM for the 8GB module) |

ARK's kernel fragment does the following:

- Moves the USB-C device controller's USB 3 lane to `usb3-0`.
- Enables a third USB 3 lane for the dual USB-A port.
- Adds UART-B as `/dev/ttyTHS3`.
- Puts UART-A in PIO mode, because the stock DMA corrupts RX at 3 Mbaud.
- Enables HD audio.
- Switches display to the HDMI DCB, with an active-low hotplug line and no HDCP.
- Caps the 16-pin FFC PCIe connector at Gen2.

The build script checks each of these in the output DTB.

Not carried over from ARK: their pad-voltage file, which is identical to stock
apart from comments, and their Orin Nano C7 link-rate patch, which only applies
to Nano modules.

### On the device

- **Orin NX module:** the same drivers and L4T userspace as `avocado-bsp-jetson-orin-nx` 0.1.0.
- **CAN:** `mttcan` for the onboard transceiver (`can0`).
- **CSI cameras:** NVIDIA's capture stack and the IMX219 driver (`/dev/video0`, `/dev/video1`).
- **M.2 Key E:** Intel AX200/AX210 WiFi and Bluetooth (`iwlwifi`, `btintel`, firmware).
- **Ethernet:** `r8169` firmware (`linux-firmware-rtl8168`).
- **`/etc/nvpmodel.conf`:** this module's power-mode table. The image ships the 16GB table, but the 8GB module has 6 CPU cores and a smaller GPU. NVIDIA's license doesn't allow committing these tables, so `scripts/fetch-nvpmodel.sh` downloads them from NVIDIA's apt repo at build time (checksum pinned) and `scripts/install-nvpmodel.sh` installs the matching one.

## JAJ hardware on Avocado

| | Linux |
|---|---|
| Console (UART2 connector) | `ttyTCU0`, 115200. Same combined UART as the devkit |
| UART1 / UART0 connectors | `/dev/ttyTHS1` / `/dev/ttyTHS3` |
| IMU (ICM-42688P, SPI1) | `/dev/spidev1.0` (spi@3230000 CS0). No kernel IIO driver in the feed; use it from userspace like ARK's `icm42688p_test.py` |
| Carrier power monitor (INA238) | `/dev/i2c-7`, address `0x45`. No hwmon driver in the feed; read it over I2C like ARK's `ina238_test.py` |
| Module power monitor (INA3221) | hwmon (`ina3221` driver) |
| CAN | `can0` |
| USB-C | Host or device. `tegra-xudc` gadget on `3550000.usb` |

## Updating

- **New Avocado snapshot:** the weekly `drift` CI job fails when the feed's newest
  `jetson-orin-nx` snapshot ships a different flash BSP. Then:
  1. Update `AVOCADO_SNAPSHOT` and `BOOTFILES_SHA256` in `upstream.env` to the values in the failure message.
  2. Run `scripts/build-carrier-bsp.sh`.
  3. Review the DTB diff (`dtc -I dtb -O dts`), then commit and tag.
- **New ARK release:** set `ARK_COMMIT`, run `scripts/update-sources.sh` then
  `scripts/build-carrier-bsp.sh`, and review both diffs.

CI (`.github/workflows/ci.yml`) reruns the generator and fails if `stone/` differs
from what `upstream.env` produces. It also builds both extensions with the Avocado
CLI, and checks on tags that the tag equals the `version` in `avocado.yaml`.

Tools for the scripts: `dtc`/`fdtoverlay`/`fdtget`, a C preprocessor, `bsdtar`,
`curl` and `perl`. On macOS: `brew install dtc`. On Debian/Ubuntu:
`apt install device-tree-compiler cpp libarchive-tools`.

## First boot on a JAJ

Flash with the serial console attached, then check the following:

- **USB-C gadget:** `/sys/class/udc/3550000.usb/state` reaches `configured`.
- **Ethernet:** find its path with `udevadm info -q property -p /sys/class/net/eth0 | grep ID_PATH`. It should be on PCIe C8 (`platform-140a0000.pcie-pci-0008:01:00.0`), as on the devkit.
- **CAN:** `can0` exists.
- **Cameras:** `/dev/video0` and `/dev/video1` exist.
- **IMU and INA238:** `/dev/spidev1.0` exists and `i2cdetect -y -r 7` shows `0x45`.
- **Model:** `cat /proc/device-tree/model` names the JAJ.
